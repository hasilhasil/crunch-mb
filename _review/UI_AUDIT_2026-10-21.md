## 一、之前模型实际上做了什么

1. **最早按文字直出 UI，然后推倒重做。** PLAN §1 记录首轮“编译通过、功能齐全，但 UI 效果与预期严重不符”，根因包含没有视觉中间稿、没有逐屏确认。
2. **9 月建立三层 UI。** UI_SPEC 结合 Clarity Vx Pro 的四分区组织、Pro-MB 风格的频段 Popover，以及下方整体控制区。HTML mockup 留有 v1–v9；沿用 Poppins、蓝/红/奶油三主题，四段使用统一 accent。
3. **逐步将底座收成状态条和 LINKED 抽屉。** 全局设置挤入底栏，详细参数交给浮层；Makeup 曾在顶部旋钮、曲线节点与面板入口之间反复调整。
4. **10 月再次朝 Pro-MB 的布局和交互改造。** UI_PLAN_V2 加入全出血频谱、全高分割线、底部手柄、双刻度、节点电平环、Range 区域、竖排 EXPERT、旋钮缓存层与四态、Tween、磨砂与阴影。抽出 BandPopover、LinkedDrawer、AnalyzerPanel 等类，并接入后端 facade。
5. **“完成”以后继续发生严重交互回归。** 文档与提交记录明确记载：R32 空闲停表导致 UI 冻结；R33 全屏子组件吞全部点击；R34 子组件禁止子旋钮接收鼠标；R35 修面板穿透、同步和层级；最新 R36 修旋钮 450° 行程、取消底栏 hover 自动展开、放大字号、补 OUTPUT。

因此，现状是多轮样式模仿、功能补齐与局部修补叠加的结果。已有组件拆分和数据接口有价值，但“像素/状态断言通过”一直没有稳定对应到“用户真的能顺畅完成操作”。

旧审查中的重复 drawDrawer、paint 中翻转光标、旋钮 450° 行程、全屏组件吞点击等，当前已有修复，不能再当成现存缺陷重复汇报。

## 二、当前明确存在的问题

### A. 会改变操作结果或显示错误

| 编号 | 优先级 | 发现与具体影响 | 当前源码位置 |
|---|---|---|---|
| U01 | P1 | **把 Mix<50% 判为旁路。** Mix=30% 仍有 30% 湿信号，但 B 灯亮、区域变暗，响应显示转向旁路分支；49%→50% 会突然切换视觉语义。实际旁路宏写入的是 0%。这是产品语义错误，不能靠统一比较单位解决。 | DisplayView.cpp:714、740、1663、2082；宏在 2221 |
| U02 | P1 | **Ratio 滑杆拖动发生数值跳变。** 起手存的是实际 Ratio（例如 4），拖动把它当 0–1 的 frac，再 clamp，再映射为 1+19×frac。4:1 起手，即使位移为 0，frac 也被夹成 1，结果写为 20:1。 | BandPopover.cpp:427–445、543 |
| U03 | P1 | **Shift 微调丢失方向。** `steps = fine ? 1 : notches` 使 Shift 模式下一律加正值。Ratio/Knee 的 Shift+向下滚轮或向下键会增加数值。 | BandPopover.cpp:452–486；DisplayView.cpp:2590 附近的键盘转发 |
| U04 | P1 | **EXPERT 的 Lookahead 显示把 1ms 与 3ms 对调。** 缓存是 0/0.5/1 对应 Off/1ms/3ms；绘制却把 1 显示成 1ms、0.5 显示成 3ms。 | BandPopover.cpp:547–550、paintExpertLayer 里的 LOOKAHEAD 行 |
| U05 | P1 | **宿主修改 Lookahead 时面板可能停在旧值。** `syncParam` 对全局 lookahead 只返回 true，不更新 sliders_[4]；EXPERT 绘制读的正是这个缓存。音频线程全量同步的兜底路径能刷新，但不能修复消息线程精确同步的缺口。 | BandPopover.cpp:562–570；DisplayView.cpp:346 |
| U06 | P1 | **MIDI Learn 是演示映射。** 点击控件按 id 生成一个“控制器号”，并非等待实际 MIDI CC；CMake 明确 NEEDS_MIDI_INPUT FALSE。作为正常产品按钮呈现会让用户误以为已经学会硬件控制器。 | DisplayView.cpp:2415–2440；CMakeLists.txt 的 MIDI 配置 |
| U07 | P2 | **Stereo Link 有参数和 DSP，却没有 UI 控件。** Parameters.cpp 注册每段 0–100%，processor 读取、DSP 使用；UI 目录没有 StereoLink 引用。与 v2“Popover 滑杆已覆盖”的交付说法不符。 | Parameters.cpp:130；PluginProcessor.cpp:280；UI_PLAN_V2 §7.3 |
| U08 | P2 | **写参没有完整的宿主手势生命周期。** 当前 src 未发现 beginChangeGesture/endChangeGesture；旋钮声明 onDragStart/onDragEnd，但面板没有绑定；backend 直接 setValueNotifyingHost。宿主能收到值，不代表能正确识别触碰、拖动结束或组织撤销。具体宿主表现需实测。 | Knob.cpp:128、150；BandPopover.cpp:355；MBBackend.cpp:43、194 |
| U09 | P2 | **实时响应图与干湿混合不一致。** 显示直接用 Makeup+段 gain dB，未计算实际每段干湿混合；Mix<50% 又直接显示 raw 分支。Mix=0 时 Makeup 也不应继续作为该段实际已施加增益。图中也没有体现全局 Mix 等后级作用。如果保留它作为动态示意，应明确标注语义，不能承诺是精确总输出频响。 | DisplayView.cpp:1624–1698；对照 MultibandDSP.cpp:480 起的实际混合 |
| U10 | P2 | **一批参数变化只同步第一个匹配项。** 消息线程在一次 timer tick 前修改同段 Threshold 和 Attack，pendingParamIds_ 会累积两项；syncUiFromParams 遇到第一个 syncParam=true 就 break，随后 timer 清空整个队列，第二项可能保持旧读数。下一次 fullSync 或重开面板才能纠正。 | DisplayView.cpp:333–357、timerCallback 消费 pendingParamIds_ 后 clearQuick |

Ratio 的正确起点应由该参数自己的归一化转换得到，不能仅修一个常数。旁路则必须先决定是否继续用 Mix 宏：若保留宏，指示至少应对应 Mix≈0；若引入独立旁路参数，需要状态迁移与兼容处理。

### B. 控件虽然可点，但操作方式不合理

1. **Input/Output Gain 用点击循环而非连续调节。** 每次 +3dB，到 +36dB 后跳到 −36dB。Global Mix 每次 +25%，超过 200% 回到 0%。用户想从 0 调到 −1dB，面板根本没有直接路径；连续量被做成循环开关。OUT 有 Alt 拖动捷径，Input Gain 没有同等入口。位置：OutputPanel.cpp:100–118。
2. **侧链频率只有四个预设循环。** 高通仅 20/100/500/2000Hz，低通仅 500/2000/5000/20000Hz；参数本身却是连续频率。用户不能在这个 UI 里直接输入 120Hz 或 8kHz。还可能选出高通高于低通的组合，面板没有解释处理规则。位置：BandPopover.cpp:207–228。
3. **单段 EXPERT 里放全局 Lookahead。** 用户在 HIGH 段操作，却会改变四段共有的延迟；缺少“全局”说明，作用域不清。位置：BandPopover.cpp:234–250。
4. **LINKED 的五把旋钮语义不同。** 前四把是差值，Mix 却是绝对值，显示还只取 Band 0。若四段 Mix 分别是 20/40/60/80，转动它会抹平差异。新版 UI_SPEC 有意规定这个例外，因此不把它当实现 bug；但必须用明显的“统一设为”表达，并显示不同值状态。位置：LinkedDrawer.cpp:255–315。
5. **在大范围背景上滚轮会修改分频。** DisplayView::mouseWheelMove 只按 x 判断频段，没有限制在绘图区有效 y 范围；未被其他组件消费的顶栏、刻度、Analyzer/Output 面板附近滚轮可能落入分频宽度修改。隐藏手势影响真实声音，且 v2 文档把它写成“缩放显示范围”。位置：DisplayView.cpp:3027–3087。
6. **精确输入自己手写，但缺少标准编辑体验。** Knob 进入编辑时先清空；确认直接 getDoubleValue，没有合法格式校验；当前类没有 focusLost 处理，也没有选择、插入位置、粘贴等标准数值编辑行为。空输入可变为 0，再被范围钳制。拖动途中按 Shift 则用新的系数重算自起点以来全部位移，可能造成读数跳变。位置：Knob.cpp:131–145、openEditor、closeEditor、keyPressedEditing。

### C. 快照可见的视觉与信息层级问题

| 问题 | 快照所见 / 实现原因 | 后果 |
|---|---|---|
| 画布很大，参数却很小 | 920×620 主屏大量面积留给曲线；频段面板六旋钮挤在约 510×216 区域；EXPERT 文字基础字号 8.5px | 需要精读和频繁寻找，放大窗口不等于版面质量提升 |
| 半透明面板承载精细操作 | 主曲线、网格、Range 区域从浮层下面透出来 | 正在调的参数与正在看的响应互相干扰 |
| 曲线/Range 的蓝色权重相近 | 主线、四段底部钟形、节点、选中填色同色叠加 | 潜在处理范围与实际处理结果不容易区分 |
| 关键动态反馈太隐蔽 | 有节点环形电平，但没有常驻、明确的每段 GR 数字；旧规格曾主动禁止 GR 读数 | 多段压缩的核心问题“哪段正在压多少”难以快速判断 |
| 底栏塞满缩写和截断 | 快照中 Natural Phas…、右上 IN/OUT 标签局促；P/S/Q/LA/OS/ANZ 连在一条低矮状态条 | 全局声音设置看起来像低优先级状态信息 |
| 信息命名混杂 | 单段 OUTPUT 实际是 Makeup，全局又有 OUT；总 POWER 与底部 BYPASS 是不同语义；中英文混排 | 同词不同作用，用户很难预测按钮效果 |
| 普通操作不断遮挡/替换 | 调单段弹层、打开 Analyzer/Output 又关闭单段面板；LINKED 独立浮出 | 缺少稳定的工作区和空间记忆 |
| 纯坐标缩放不是响应式布局 | sx 按宽、sy 按高；文字有全局 1.16 倍、部分按高缩放、部分固定；旋钮与抽屉又各自限幅 | 极宽/极高、最小尺寸和 DPI 下存在错配风险，需尺寸矩阵验证 |

视觉判断以快照为依据；没有把“我不喜欢的风格”当成程序错误。历史“统一三主题、统一 accent”属于产品决策，也不能直接算 bug。

## 三、为什么断言全绿仍然不好用

- 许多测试直接调用 DisplayView 的 mouseDownForTest 等钩子，绕过真实组件鼠标分发；R33/R34 已经留下明确事故记录。
- 有的测试验证“数值发生变化”，却没有验证方向、连续性和起手不跳变；Ratio 与 Shift 负向问题需要这种语义断言。
- 普通测试默认字体倍率 1.0，真实编辑器设为 1.16；快照工具才显式设真实倍率。旧像素断言不能直接代表用户看见的排版。
- 测试中 paintForTest 手动绘制直接子组件不等于真实组件树合成；其 translation 用负坐标也只因当前全屏子组件在原点而未暴露。后续应直接使用真实组件快照和事件分发。
- UI_PLAN_V2 同一文件仍混有 79/86 参数、1936/1982 行 DisplayView、hover-open 与最新 click-only、“多选完成”与单选扫段等互相覆盖的说法。当前 DisplayView.cpp 已约 3910 行。文档中的完成标记应被当作历史记录，不能作验收证据。

## 四、我会怎样整体重绘

### 推荐主方向：稳定控制台 + 大图形区

保留四固定频段、分频直接操作、双层频谱、家族字体与三主题。先确定正确的数据/交互语义，再整体绘制组件，避免继续在当前大画布上堆补丁。

- **顶部：清晰的产品与全局状态。** Crunch MB 名称、真正的插件旁路；相位模式、OS、Lookahead 明确标注；有延迟变化时给出延迟信息。去除演示 MIDI 功能。Undo/A-B 只有真实接通后才出现。
- **中部：频谱与动态视图。** 频谱用低对比中性色；实时动态曲线使用主强调色；Range 降到低透明度辅助层。分频边界可拖、频率可双击输入。四段标签显示简短频率范围和明确的 GR。节点垂直拖动的作用始终一致。
- **下部：稳定的频段控制台。** 点击 Low/Low Mid/High Mid/High 原位切换参数，保持六个主要控件的位置不变。Threshold、Ratio、Attack、Release、Range、Makeup、Mix 分组排列；高级侧链与 Stereo Link 在同一区域展开，不盖住其他控件。LINKED 用明确的目标选择与偏移/设值说明。
- **右侧：常驻 I/O。** 输入/输出电平、峰值、可编辑增益、全局 Mix 与自动增益。试听模式离开 Output 时有持续可见的提示，提供一键返回。

建议以约 **1100×740** 的逻辑尺寸设计首稿；正文/读数约 13–14px，辅助标签至少 11–12px，操作目标一般 28–32px 起。小窗口重排或切紧凑布局，放大优先增加图形面积，不能把所有控件随宽高分别拉伸。具体数值需要在真实宿主和 DPI 下定稿，不是性能保证。

这会改变旧规格里“频段参数只在 Popover”的约束，是我提出的新方案，不宣称已获得你对该变更的确认。

### 保守备选：保留 Popover，但让浮层可停靠

如果仍偏好 Pro-MB 式二级菜单，保留点击频段弹出；改用近不透明背景、清晰字号、稳定控制位置；自动避让选中节点和主要曲线；EXPERT 展开增加实际面板空间，而非盖在旋钮之上；允许固定到下方控制区。这样保留原交互偏好，也能降低遮挡和层级复杂度。

### 实现与验收顺序

1. 先修 U01–U06，明确旁路、Mix、显示曲线与参数作用域，关闭误导性的演示功能。
2. 做两个完整可操作视觉稿，至少覆盖默认/播放/频段调节/高级设置/窄尺寸。确认布局后才移植成 JUCE 控件。
3. 以一个频段做完整纵向样板：真实输入、拖动、回读、文本、宿主手势、GR、旁路，接通后再扩展四段。
4. 保留 DSP 与稳定参数 ID，UI 使用后端元数据的范围/默认值/归一化，避免再次手抄两套。若新增真实旁路参数，另做工程状态兼容方案。
5. 用真实组件事件链测试，再在宿主中验证自动化、重开界面、混合值、临界值、三主题及 DPI。帧率、CPU、音频稳定性都要播放时测量，不能用静态截图或断言数代替。

本次内嵌示意中的曲线和读数是设计模拟数据，没有连接插件 DSP；它表达的是布局、层级和参数操作方向。
